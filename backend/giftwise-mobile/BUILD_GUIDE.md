# GiftWise mobile build guide

Mobile v0.3 is for hosts and guests. Administration remains in the original web application; the web app returns 404 for `/admin` and `/backend/api/admin` to the app.

## Local standalone Android preview

Use a supported Node version (22.13+ in 22.x or 24.3+ in 24.x), Java 21 and the Android SDK. Install this package and the main web app's dependencies (`npm --prefix ../../web ci`), then run:

```sh
npm run web:build
npm run web:start
# In a second terminal:
npm run build:android:local
```

The script generates Android files from Expo config, compiles a release-mode application using the local debug signing key, and embeds JavaScript. Output: `artifacts/GiftWise-android-host-preview.apk`. It does not use Metro, Expo Go, EAS account access, or store publishing.

This x86_64 emulator preview uses the actual local frontend/backend through ADB-forwarded `http://127.0.0.1:3100`. The web/backend services must be running. See `LOCAL_ANDROID.md` for emulator installation and launch. The preview is not a production-signed or public-distribution app.

## Public Android/iOS distribution

Configure the following under your organization's control:

- `EXPO_PUBLIC_GIFTWISE_WEB_URL`: deployed HTTPS host-only frontend origin.
- `GIFTWISE_ANDROID_PACKAGE`, `GIFTWISE_IOS_BUNDLE_ID`: owned release identifiers.
- `GIFTWISE_EAS_PROJECT_ID`: actual EAS project UUID if using cloud builds.
- Actual payment-provider redirect origins where needed, signing credentials, and store account metadata.

Use the EAS profiles in `eas.json` after account/project association. Local preview HTTP is allowed only for loopback/emulator hosts under an explicit preview flag. Production configuration refuses that flag and requires HTTPS. Never put account passwords or provider secrets into public Expo variables.

An iOS binary requires Xcode/signing or an appropriately configured cloud build; no iOS binary is supplied by the local Android command. Physical Android phones need a matching architecture build and reachable frontend address. No store build is submitted automatically.

## Before release

Verify real customer login, event/guest flows, provider checkout/cancellation, file uploads/exports, account recovery and permissions on supported devices. Platform-administration must remain inaccessible through native links, login redirects and the deployed mobile portal. Public URLs generated by the backend must point at the intended frontend. Do not use the local test origin for public distribution.
